## 1. The rule

> **Any numeric claim in a doc that is derivable from the code lives inside a `<!-- probe:key -->…<!-- /probe -->` marker and is regenerated by the audit script, not maintained by hand.**

The example that motivates the pattern: `docs/README.md:38` in the reference implementation says "180 tracked docs, 87 marked historical." Those two numbers are `find docs/ -name '*.md' | wc -l` and `grep -l 'status: historical' docs/**/*.md | wc -l` — a hand-written pair that drifts the moment anyone adds or archives a doc. Enclosing them in probe markers and regenerating from the audit script keeps them true forever.

---

## 2. The marker syntax

```md
The repo currently tracks <!-- probe:tracked-docs -->180<!-- /probe --> docs,
of which <!-- probe:historical-docs -->87<!-- /probe --> are marked historical.
```

Rules:

- The opening tag is HTML-comment `<!-- probe:key -->`. The closing tag is HTML-comment `<!-- /probe -->`. Both are invisible in rendered markdown.
- Between the two tags is the rendered value — a number, a short list, or any string.
- The key (`tracked-docs`) matches an entry in `«PROBE_REGISTRY»` (see §3).
- The value between the tags is **the last regenerated value**. Regeneration overwrites it.
- Probe markers may sit inside table cells, headings (rare — see below), body text, and code fences (limited — the runner has to know the fence isn't code).

Probes in headings: only when the *number* is the semantic anchor of the heading, and even then prefer prose. `## <!-- probe:release-count -->42<!-- /probe --> releases` renders as `## 42 releases` — the anchor becomes `#42-releases` and stays stable (unlike an emoji in a heading, which the GitHub slugger strips). But numbers-in-headings drift the reader's mental link; use prose unless you have to.

## 3. The probe registry

```ts
// «PROBE_REGISTRY» — scripts/tools/probes.ts
//
// Each probe is (key, query) → string. The query runs against the live repo.
// Keep queries FAST — the runner executes every probe on every regeneration.

import { globSync } from 'node:fs/promises';
import { readFileSync } from 'node:fs';
import { execSync } from 'node:child_process';

export const PROBES: Record<string, () => string | Promise<string>> = {
  'tracked-docs': () =>
    String(globSync('docs/**/*.md').length),

  'historical-docs': () =>
    String(
      globSync('docs/**/*.md')
        .filter((p) => /^status:\s*historical/m.test(readFileSync(p, 'utf8')))
        .length
    ),

  'release-count': () =>
    execSync("git tag -l 'v*' | wc -l", { encoding: 'utf8' }).trim(),

  'api-route-count': () =>
    String(globSync('src/app/api/**/route.ts').length),

  'domain-count': () =>
    String(globSync('src/domains/*/').length),

  // ...
};
```

Guidelines:

- Each probe returns a string (the runner substitutes the string between the marker tags verbatim).
- Probes should be **pure functions of the repo state** — no network calls, no clock reads (unless the clock IS the probe subject).
- A probe that takes more than ~500ms is a smell — every doc regeneration runs every probe.
- New probes are added here + tagged in a doc with `<!-- probe:new-key -->PLACEHOLDER<!-- /probe -->`; the first regeneration fills the placeholder.

## 4. The runner

```ts
// scripts/tools/docs-audit.ts — invoked as «PROBE_SCRIPT»
import { globSync } from 'node:fs/promises';
import { readFileSync, writeFileSync } from 'node:fs';
import { PROBES } from './probes';

const MARKER = /<!--\s*probe:([\w-]+)\s*-->([\s\S]*?)<!--\s*\/probe\s*-->/g;

let filesTouched = 0;
let markersUpdated = 0;
let unknownKeys: string[] = [];

for (const path of globSync('docs/**/*.md')) {
  const text = readFileSync(path, 'utf8');
  let changed = false;
  const updated = text.replace(MARKER, (whole, key, current) => {
    const probe = PROBES[key];
    if (!probe) { unknownKeys.push(`${path}: probe:${key}`); return whole; }
    const fresh = String(probe());
    if (fresh === current.trim()) return whole;
    changed = true; markersUpdated++;
    return `<!-- probe:${key} -->${fresh}<!-- /probe -->`;
  });
  if (changed) { writeFileSync(path, updated); filesTouched++; }
}

if (unknownKeys.length) {
  console.error('unknown probe keys (add them to `«PROBE_REGISTRY»`):');
  unknownKeys.forEach((k) => console.error(`  ${k}`));
  process.exit(1);
}
console.log(`${markersUpdated} markers updated across ${filesTouched} files`);
```

Two flags matter:

- **`--check`** (add if needed): dry-run — exits non-zero if any marker would change. This is the CI mode — a stale doc fails the PR.
- **Default** — rewrites files. This is the pre-commit / local mode.

---

## 5. Wiring

- **Pre-commit hook** — run in write mode; if `git status` shows changes after the run, `git add` them into the same commit. A stale probe never survives a commit.
- **CI** — run in `--check` mode as part of `ci:quality`. Any diff → PR fails.
- **Weekly sweep** — the quarterly `MANAGER_DOC_FRESHNESS.md` sweep runs the audit; the report includes the count of markers updated (a healthy repo has zero — writes drift-out during commits).

---

## 6. Extending — non-numeric probes

The mechanism is not limited to numbers. Any string derivable from the repo works:

```md
## Current release

<!-- probe:current-release -->v1.38.0<!-- /probe --> (cut <!-- probe:current-release-date -->2026-09-04<!-- /probe -->)
```

Or an entire small list:

```md
## Domains

<!-- probe:domain-list -->
- auth
- billing
- content
- feedback
<!-- /probe -->
```

For lists, the probe returns the multi-line rendered string. The mechanism is the same — the runner substitutes between the tags.

**Do not** use probes for long-form prose. If the substitution is more than ~5 lines, the doc is now a template rendered from the repo, and it belongs in a generator, not in-place regeneration.

---

## 7. Anti-patterns

- **Numeric claim in a doc without a probe marker.** Every hand-typed number drifts. If the number is derivable, mark it; if it's not derivable (a target, a decision), name it as a target ("we aim for ≤ 50 API routes") not a state.
- **Probe key with a `_` instead of a `-`.** Consistency — the registry uses kebab-case; the docs match.
- **Probe that depends on the current time.** Docs become non-deterministic across runs; the CI `--check` mode flaps.
- **A probe that fetches from the network.** Regeneration on a plane fails. Every probe is a pure function of the working tree.
- **`<!-- probe:foo -->` without `<!-- /probe -->`.** The regex is non-greedy; a missing close tag will silently swallow every doc after it.
- **Manually editing the value between marker tags.** The next regeneration overwrites the edit. If the value is wrong, the *probe* is wrong — fix it in `«PROBE_REGISTRY»`.

## 8. Verification checklist

- [ ] `«PROBE_SCRIPT»` exists and runs both write and `--check` modes.
- [ ] `«PROBE_REGISTRY»` lists every probe key used across `docs/`.
- [ ] The unknown-key check exits non-zero, listing the offenders.
- [ ] Pre-commit hook runs the writer; CI runs `--check`.
- [ ] `MANAGER_DOC_FRESHNESS.md` output format includes `Markers updated this sweep:` as a headline number (0 in a healthy repo).
- [ ] No numeric claim in `README.md` / `CATALOG.md` / `docs/**/*.md` is hand-typed if it's derivable.
